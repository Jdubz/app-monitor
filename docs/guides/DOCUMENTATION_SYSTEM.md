# Documentation System

**Version:** 1.0.0
**Date:** 2025-11-18
**Purpose:** To provide a clear and concise guide to the documentation system for the App Monitor project.

---

## Principles

1.  **Actionable:** Every document should guide action or decision-making.
2.  **Current:** Documentation should be kept up-to-date. Outdated documents should be archived.
3.  **Organized:** A clear hierarchy should be maintained.
4.  **Concise:** Communication should be direct and to the point.

---

## Structure

-   `/architecture`: System architecture, design decisions, and constraints. These are permanent documents.
-   `/guides`: How-to guides, runbooks, and setup procedures. These are permanent, updated documents.
-   `/plans`: The project roadmap. This is a living document that is updated as the project progresses.
-   `/technicalDesigns`: Detailed implementation specifications for features. These are temporary documents that may be promoted to permanent documents.
-   `/archive`: Outdated and completed documents.

---

## The Roadmap

The single source of truth for the project's roadmap is `docs/plans/PRIORITIZED_FEATURE_ROADMAP.md`. This document is updated regularly to reflect the current state of the project.

---

## Maintenance

-   **Archive, don't delete:** When a document is no longer relevant, move it to the `docs/archive` directory.
-   **Keep it current:** Regularly review and update the documentation to ensure it is accurate and up-to-date.
-   **Stay organized:** Follow the directory structure outlined above.
